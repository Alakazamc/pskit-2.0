## 发布与验收

- 固定镜像和 dist 先在隔离 Staging 验收。通过直接私有 API 及 `http://10.9.8.1:18132` 的真实 Nginx 入口验证登录、文件、Agent SSE、Token/GPU 配额、超额拒绝和模拟 AF3；生产表计数及 LiteLLM 计费摘要在烟测前后保持一致。
- Staging CSRF 正反向验证通过：带刷新 Cookie 但缺少 CSRF 的刷新请求返回 `403 CSRF_FAILED`；精确 Origin 与匹配令牌返回 200。Staging 完成后停止三个专属 Compose 项目，没有使用 `down -v`，账号和卷均保留。
- 生产切换前确认活动 Agent Run 与 Job 均为 0。仅定向替换 backend；Supabase/PostgreSQL、LiteLLM、AF3 callback proxy、A6000 接收器和宿主 Nginx 均未重启。
- PostgreSQL 由 schema v7 兼容扩展到 v8，增加四张 `auth_abuse_*` 表。认证滥用模式仍为 `off`，这些表暂不参与生产请求；CSRF 使用独立、未输出到日志的 64 位十六进制密钥。
- 生产运行镜像健康且 restart count 为 0；运行模式为 `live / pi / callback`，CSRF 配置校验通过。`/health/ready` 返回 ready。
- HTTPS `/login` 返回 200，未登录 `/api/v1/usage` 返回 401，公网 `/internal/` 返回 404，公网 `/admin/models` 返回 Nginx 403，无刷新 Cookie 的 `/api/v1/auth/csrf` 返回 204。
- 公网 `/login` 返回的 HTML SHA256 与发布 `index.html` 一致；发布包内 386 个前端文件逐一与生产静态目录核对一致。旧 hash assets 保留，index 原子替换，无需 reload Nginx。
