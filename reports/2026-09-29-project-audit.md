# PSKit 2.0 项目审查、修复与验收

日期：2026-09-29。范围：当前仓库及交付脚本；真实外部科学服务和生产服务器未在本次操作中重新部署或运行。

## 项目工作方式

PSKit 是面向蛋白质与核酸分析的科研工作台。用户通过 Vue 页面注册、登录、建立对话；FastAPI 将轮次、消息、任务与文件归属写入数据库。LangGraph 执行知识检索、工具规划、工具执行和回答生成；SSE 向浏览器传递事件。科学任务由独立 Worker 从持久化队列领取，调用本地兼容运行环境、MCP 或 AlphaFold3，再把输出登记为可下载产物。

主要边界：

| 模块 | 职责与实现 | 本次重点 |
| --- | --- | --- |
| 用户界面 | Vue、Pinia、Router；对话、任务、工具与管理员页面 | 跨会话串流、失败提示、审批、恢复与草稿 |
| 登录与权限 | HttpOnly Cookie、密码哈希、用户归属、管理员引导 | 首位管理员注册、并发会话上限 |
| Agent | LangGraph、持久化 AgentTurn、租约、后台线程与 SSE | 有界准入、幂等重放、异常终态 |
| 科学任务 | SQL 队列、Worker 租约、重试链、模型/MCP 适配器 | 多进程配额、输入契约、重试与产物 |
| 科研上下文 | 会话关联的 ResearchRun、候选、阶段、评分、报告 | 任务和产物不能混淆；用户所有权必须保留 |
| Harness | 单独的执行契约、事件、outbox、projection 与迁移桥 | 默认路线仍由受控启动注入决定，不能把代码存在当作已上线 |
| 知识检索 | Qdrant 与 embedding；不可用时关键词检索 | 无向量集合时仍应能备份 |
| 部署与交付 | Docker Compose、迁移、备份、离线包、CI | 路径一致性、权限、私有依赖与敏感文件排除 |

## 已确认问题及修复

| 问题 | 影响 | 修复 |
| --- | --- | --- |
| 首位管理员 UI 缺少引导令牌，关闭注册会封死初始化 | 新生产部署无法从页面完成开户 | 注册状态明确返回引导需求，表单传令牌；初始化后遵守关闭注册配置 |
| 示例信任固定私网反向代理地址 | 移交到另一环境时信任边界错误 | 默认留空，由部署者指定真实直接代理 |
| SQLite 任务配额只用进程内锁 | Web 和 Worker 并发时突破资源上限 | 统一数据库事务锁；SQLite 写锁、PostgreSQL advisory transaction lock |
| 登录会话上限存在相同并发竞态 | 并发登录突破活跃会话上限 | 按用户串行化淘汰与新建；首次管理员认领也串行化 |
| Agent 线程池等待队列没有业务准入上限 | 慢请求积累、占满内存与执行资源 | 数据库记录全局及每用户活动轮次上限，超限返回 429，已有轮次可重放 |
| PepCCD 使用手写类型转换及重复校验 | 空值产生 500、小数被截断、非法序列进入队列 | 一个共享 Pydantic 参数契约，同时供任务准入和 MCP 请求使用 |
| 任务列表每个任务单独查询关联数据 | 页面轮询产生大量重复查询 | 批量装载产物与重试链；20 个任务由 61 次 SELECT 降至 3 次 |
| 对话切换时旧请求继续修改当前页面 | 回复、工具事件、产物跨会话显示 | 抽出会话控制逻辑，按会话和请求版本隔离；切换取消订阅 |
| HTTP 环境直接调用 randomUUID | 点击发送可能卡住 | 客户端标识兼容非安全上下文，统一调用入口 |
| SSE 错误终态与正常完成混淆 | 用户看见就绪，却没有正确结果 | 明确失败状态、错误信息与按原轮次恢复；保留未接收的草稿 |
| 后端审批协议没有前端确认入口 | AlphaFold3 等高成本操作无法继续 | 展示待审批操作，提交明确的 approval_id，历史恢复保留审批状态 |
| 任务页面只加载前 100 条 | 旧任务和成果不可访问 | 新增每页 20 条的分页；轮询固定当前页并丢弃过期响应 |
| Cookie 过期后页面继续显示已登录 | 保护接口持续失败 | 401 清理认证状态并跳转登录，保留原访问位置，避免登录页跳转循环 |
| Linux 启动脚本缺少执行权限 | 新 checkout 直接启动 Permission denied | 修复 Git executable mode |
| 通用 Worker 默认申请 16 核 CPU | 4 核机器上 Docker 拒绝创建容器，CI 实际复现 | 基础部署改为 Worker 2 核；16 核/32GB 仅作为可调整的 A6000 科学配置默认值 |
| 迁移脚本仅凭单表存在就 stamp head | 残缺数据库被伪装成最新版本 | 校验已有表列与关键结构，只对已验证兼容 schema 对齐 0003；后续迁移正常执行 |
| 数据目录、数据库、产物目录硬编码不一致 | 自定义/嵌套 Docker 部署的持久化路径错位 | 数据库与产物默认路径从同一数据目录派生 |
| 定时备份默认引用未交付的私有文件 | 新部署每天备份失败 | 默认使用当前项目配置，额外配置显式提供 |
| 备份把大型产物与快照堆到受限 /tmp | 产物增长到 512MB 以上后备份失败 | 数据流直接输出到备份目的地，避免整份暂存 |
| 可选 Qdrant 集合不存在使全部备份失败 | 使用关键词检索的部署无法备份 | 明确记录没有向量集合，继续保留数据库和产物备份 |
| 离线包遍历未跟踪文件且排除规则不足 | 私密文件或嵌套环境文件可能泄漏 | Git/来源清单白名单，加敏感路径排除；保留中文文件名 |
| 科学镜像默认引用未交付的私有基础镜像 | 干净机器无法复现完整科学 Worker | 基础镜像改为显式必需前置条件；支持指定科学 overlay 导出镜像，文档明确授权运行环境仍需单独提供 |

## 重构取舍

本次重构围绕已经出现的故障：共用数据库事务锁、共用 PepCCD 参数模型、任务批量序列化、独立的前端会话控制器。没有替换数据库、重写全部 Worker 或默认启用 Harness；这些结构性迁移需要独立的数据兼容和部署验收。

## 验收与剩余边界

本地最终验收：后端 36 项、前端单测 21 项、Chromium 浏览器 9 项、交付/备份脚本 4 项全部通过；Ruff、Mypy、前端构建与 lint 通过；生产前端依赖审计 0 项漏洞。CI 另行验证锁定依赖、镜像构建、全新 Compose 启动和生产首管理员登录流程，结果链接见对应 PR。

回归覆盖数据库多进程竞争、任务列表权限与查询数量、错误科学参数、数据库迁移、离线文件排除、备份流、前端对话切换和审批。Agent 集成测试还覆盖真实路由、SSE、消息落库、幂等重放，以及 Agent 到 Worker、产物登记、下载与跨用户访问拒绝。

浏览器回归使用本地真实浏览器与受控 API 响应，Agent 集成测试对外部 LLM/科学模型进行替身注入。这验证产品与执行协议，不等于真实 Coral、PepCCD、AlphaFold3 推理成功。外部 MCP 网络、校园网在线状态、GPU、授权模型权重及科学基础镜像仍需在目标服务器验收。PostgreSQL 锁路径实现已保留，本次并发实测为 SQLite。

任何不完整的旧 schema 都应先备份再做针对性迁移；本次脚本会拒绝错误标记为已完成，而不会猜测缺失数据。PR 合并也不会自动更新阿里云或 A6000 上已经运行的实例。
