# 管理 API 契约（冻结 v1）

前缀 `/api/v1/admin`。浏览器使用当前 Supabase `Authorization: Bearer <token>`；每个请求读取服务器当前角色。`AdminMe = {user_id: string, roles: string[], permissions: string[], service_ids: string[]}`。普通用户/游客为 403，无 token 为 401。错误统一为 `{detail: {code: "ADMIN_FORBIDDEN" | "REVISION_CONFLICT" | ...}}`，版本冲突为 409。所有列表返回 `{items: [...], next_cursor: string|null}`，参数 `limit=50`（1..100）、`cursor`（不透明）。

完整 Pydantic 源：`new_backend/app/contracts/admin.py`；OpenAPI 可生成 TS 类型。权限字符串：`models:read`, `models:write`, `models:publish`, `services:read`, `services:write`, `services:publish`, `quotas:read`, `quotas:write`, `jobs:read`, `jobs:cancel`, `sandboxes:read`, `sandboxes:drain`, `usage:read`, `usage:reconcile`, `audit:read`。platform_admin 全部；service_maintainer 仅 models:read/services:read/services:write/jobs:read（服务、作业限制到 service_ids）；quota_operator 为 quotas:read/quotas:write/jobs:read/jobs:cancel/sandboxes:read/sandboxes:drain/usage:read/usage:reconcile；auditor 为全部 read。维护者无发布和额度写权限。

修改示例：`PUT /llm-aliases/lab-chat/draft`，`{"expected_revision":0,"reason":"开放给实验成员","allowed_user_ids":["user-1"],"allowed_group_ids":[],"purposes":["chat","analysis"],"supports_images":false,"reasoning_levels":[],"default_for_purposes":["chat"]}`。返回 `{id:"lab-chat",revision:1,state:"draft",gateway_available:true,gateway:{id:"lab-chat",supports_images:false,reasoning_levels:[]},draft:<ModelDraft>,published:null}`。发布使用 `{expected_revision:1,reason:"审核通过并发布"}`，返回 revision 2 / state published。空授权名单明确无授权；groups 必须来自服务端成员表；图库、发送和每次实际代理调用均复查当前策略。managed 模式须服务器显式开启，默认保留既有网关模型行为。

额度示例：`{"expected_revision":0,"reason":"调整实验资源上限","token_monthly_limit":100000,"gpu_daily_minutes":60,"cpu_daily_core_ms":600000,"concurrency_limit":2,"storage_limit_bytes":1073741824}`。`tokens` 单位 token，`gpu` 单位 GPU 分钟，`cpu` 单位 CPU 核毫秒；所有 counter 含 limit/used/reserved/remaining，调限不改 used/reserved。实际 B 账本保持整数 GPU 毫秒；管理页分钟 counter 的 used/reserved 向上取整、remaining 向下取整，客户端直接使用服务器返回的 remaining。AdminUser.storage_limit_bytes 可为 null（既有成员没有配置存储上限）；0 是明确禁用上传，LimitsUpdate 中此值始终为非负整数。

服务保存 `ServiceDraft` 中 capabilities 使用已有 `CapabilityVersion`，包括 id/version/input_schema/output_schema/required_usage/accepted_sources/allowed_users/max_budget/concurrency/max_execution_seconds/cancellation/limit_mode/exclusive_process。draft 的 visibility 固定 draft。endpoint_ref/credential_ref 必须在服务器批准的引用配置中；不会从浏览器接收真实地址或密钥。连接检查只做 bounded GET/实际 MCP tools/list；失败返回 status failed，不运行推理。discovery 只记录发现结果，不改变草稿或开放状态；kind=schema 的 checks 必须发现实际 input_schema/output_schema 并与草稿一致，才设为 validated，revision 不增加。显式 Schema 检查失败会恢复 draft 并清空验证 digest，阻止创建/发布引用该草稿的包；此前已发布的不可变能力保留。检查进行期间草稿 revision 改变，则结果提交返回 409，不覆盖新版本验证状态。未提供输出 Schema 的 MCP 服务可以发现，但不会假定草稿输出约束已经验证。发布包请求如 `{"expected_revision":0,"reason":"提交科研服务发布包","services":[{"service_id":"rna","revision":2}]}`，返回 release_id/revision/state/services/impact；发布管理员审核后的包更新 B 的不可变 capability registry 和审计/outbox 同一事务。

取消响应 state=requested 表示远程停止尚未确认；只有业务已确认 cancelled 才 state=confirmed。对账必须 stopped=true、terminal_status、usage 及 evidence；未知用量为 null，绝不补零。审计和作业列表不暴露原始科研输入、JWT 或秘密。

旧 AF3 行由 `service_id=null` 且 `capability_id="af3"` 识别。通用 cancel 路由调用真实旧 AF3 业务操作；已启动任务进入 cancelled/pending_reconciliation 时仍返回 requested 并保留预占，未启动任务取消才可立即 confirmed。其对账使用独立请求：`{"expected_revision":2,"reason":"核验旧执行器停止记录","actual_gpu_minutes":9,"stopped":true,"evidence":"监督进程确认任务已停止的回执","source":"legacy_wall"}`。actual_gpu_minutes 为严格整数 0..1440，source 仅 legacy_wall；不把 gpu_device_ms 伪转换成旧分钟。事务保留原终态、记录审计和停止证据并检查 revision，返回安全 AdminJob。旧 PUT `/af3/jobs/{id}/gpu-usage` 继续支持 X-Admin-Key 运维载荷；带 JWT 的浏览器请求返回 422/USE_AF3_RECONCILIATION_ENDPOINT，必须使用上述强约束端点。旧对账审计读取只返回用户/作业 id、原生分钟、source、reason 和时间，不包含输入或 lease token。
