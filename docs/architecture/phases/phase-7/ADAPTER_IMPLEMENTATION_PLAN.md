# Phase 7 续作：本地准入、接收器观察与延迟回归

日期：2026-10-10。继承 [任务书](../../REMEDIATION_SPEC_2026-10-10.md) 和用户“开始干吧”的继续实施授权。起点 `a414461`；已测业务源码 `ff873b2`。本页是原计划的补充，不改变现有公开 API。

## 范围

在本地完成发布控制器缺失的真实适配器及合成联调，重新测量首持久增量。专用 PostgreSQL17 容器使用 tmpfs、loopback 随机端口、随机测试 schema；不读取生产配置、连接云端、运行真实模型/GPU、修改真实数据库或搬目录。已有未提交的 All in Luna/性能资料保留。

## 1. 事务性准入

- 门禁放入现有私有 PostgreSQL schema，作为单独的 admission component 显式迁移；核心 schema 版本13不变，启动不执行 DDL。
- 新工作提交和领取在同一事务持有现有准入锁，检查持久门禁，然后预占/写入/领取。适配器关闭门禁使用同一锁；其成功回执意味着先前准入事务已结束，新事务无法越过检查。
- 门禁绑定环境、项目、适配器、资格报告摘要、前后 Manifest 和 owner nonce。只允许同身份幂等 enter/verify/release；时间过期仅使观察回执失效，不自动开放。
- 覆盖 Agent、legacy AF3、generic Compute、Workspace Attempt、辅助标题任务和后台领取；取消、既有结果/回执/结算允许继续。
- 默认不启用，以兼容尚未安装组件的历史部署；显式启用后组件缺失、绑定错误必须拒绝启动或准入。私有只读观察接口证明运行中服务启用了指定实现，CLI将其与自身数据库身份核对。
- Manifest 的可选 `admission` 元数据保持旧文件可读；API更新要求当前、目标及回退制品具有匹配的资格元数据。不支持门禁的历史镜像不能作为此控制器的 API 回退对象。
- 保留闭锁跨 CLI 失败、后台进程重启和观察过期的行为。关闭期间的 smoke 使用预先写入的合成终态资料进行认证、SSE重放、文件归属/下载检查，不给普通管理账号添加准入绕过。

## 2. 接收器观察

- 在已有统一接收器进程添加默认关闭的私有、认证、只读入口，不增加微服务或公网端口。
- 自动观察 CORAL、兼容 AF3、Tools AF3 三份真实结构的 SQLite journal、outbox、spool 及领取中/执行中状态。缺文件、未知结构、锁阻塞、跨观察修改、不完整启动不能报告全零。
- 输出保持既有 `pskit.receiver-activity.v1` 四个计数，不包含任务内容、凭据或模型文件。
- 控制器按精确 URL 从权限0600的私有文件读取认证信息，禁用代理及重定向；保持原有只读/Web配置兼容。

- 最终分别记录默认配置与启用门禁的开销；本地合成结果不代表真实供应商首 token 或公网 TTFB。

## 验收与回滚

- 先运行新增失败测试，再实现并跑 SQLite/真实 PG 跨连接并发、身份错配、进程/CLI中断、恢复、部分观察及认证边界。
- 独立审查后执行后端、部署、契约、Compose和相关 Pi 回归；报告 skip 和环境故障。
- 准入、接收器、性能修改分别提交。回退代码前必须确认没有持有门禁或活动/未知工作；不删除门禁记录、账本、journal 或 spool，不降级核心数据库。
- 真实 Staging、供应商调用、宿主 adoption、备份恢复 RPO/RTO和目录迁移仍需独立环境验收。新增本地适配器的存在不等于已安装/独立资格合格，不生成虚构云端 Manifest。

## 分工

主代理负责契约、整合、独立审查和记录；运行时代理负责门禁及 CLI；工具代理负责接收器观察和认证读取；基准代理负责复现、跨度测量及事件管线。各代理按文件归属修改，发布控制器只在分别约定的函数范围编辑。
