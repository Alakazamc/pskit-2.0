# Phase 2 迁移与回滚

本阶段无 schema 迁移，无线上部署。历史数据、卷、凭据和旧 CI 保持原样。

- CI/Manifest/合成配置入口可分别 revert；不涉及线上状态或数据库回退。
- 生成物同步是独立提交；回退时用匹配版本的 Python 导出器与 TS 生成物，运行契约 checker。不要只回退一份 JSON 造成客户端漂移。
- 测试基线修复独立于应用修复；回退仅影响本地/CI fixture，不能用旧 fixture 推断线上功能退化。
- 导出工具修复独立提交：不建议恢复遗漏专属表的旧判断。降级仍要求专属表为空并先做人工备份；本次未执行任何真实导入/导出。
- 本地新镜像和 PG 临时容器仅用于此轮验证。最终可按准确名称删除本任务容器，不能 prune 或删除已有卷/历史文件。

Phase 2 完整资格须等待固定 LiteLLM callback 门禁；远端 CI 必须在另行获准 push 后查看真实结果。
本地门禁不能代替线上防护或 Staging 验收。后续 Phase 3 的源码开发可继续，但不能据此签发生产可用 Manifest。
