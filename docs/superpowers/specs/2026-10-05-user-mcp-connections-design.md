# 用户 MCP 连接入口设计

日期：2026-10-05。状态：设计补充，尚未实施。

本设计扩展[Skill 与工作空间入口设计](2026-10-05-user-skills-workspace-ui-design.md)。用户新增要求是：侧栏增加 MCP，用户可以启用平台科研模型服务、添加自己的 MCP，并获得内网服务接入指南；视觉沿用同一套 ChatGPT 式简洁交互。本轮扩展静态设计稿与规格，不把上一版设计审阅视为正式实现批准。

## 1. 连接方式与产品边界

推荐默认路径：

```text
用户浏览器 → PSKit Python / Pi → HTTPS MCP 服务
                                 ↓
                       ngrok → 用户电脑 / 实验室内网服务
```

Pi 仍在平台用户沙箱中运行；Python 保存连接、密钥、授权与调用记录，通过受控连接代理调用 MCP。浏览器提交配置和展示状态，不转发实际工具调用。因此用户关闭网页后，已建立的后台任务可以继续；本机服务或隧道停止时则不能承诺远端任务仍可交互。

浏览器访问 LAN / localhost **有条件可行**：受 CORS、HTTPS / mixed content、Local Network Access 权限和浏览器版本影响。即使成功，也不会让云端 Python 自动获得到该 LAN 的网络路径。直接浏览器代理方案需要页面持续在线，并额外处理消息可信性、断线和密钥，本期不作为默认实现。

ngrok 暴露的是选定端口的服务入口，不会把计算任务迁到 PSKit，但**隧道本身不证明数据和资源不会外泄**。需要服务验证有效凭据、限定可用工具；请求 / 返回数据经过 ngrok 和平台，交给 Agent 的内容可能进入所选模型上下文。指南用准确的范围说明，避免“完全不外泄”的承诺。

连接方式比较：

| 方案 | 用户体验与边界 | 本期选择 |
| --- | --- | --- |
| 后端 → HTTPS MCP，内网通过 ngrok | 用户添加 URL 与认证；云端可持续运行；需要本机服务 / 隧道在线 | 默认 |
| 浏览器 → 本地 MCP，再转发到后端 | 特定浏览器可用；CORS / 权限 / 离线限制，密钥进入网页进程 | 后续独立研究，不在本期开箱即用 |
| 本机轻量连接器主动连云端 | 无需公开本地端口，适合长期运行；要安装守护进程、管理配对与可信消息 | 预留 adapter，先不加入必装步骤 |

## 2. 当前系统与缺口

现有 `RemoteMcp` / `MultiRemoteMcp` 支持配置的 Streamable HTTP、工具发现、命名空间和调用；`GET /mcp/tools` 按授权过滤，调用有输入 schema 校验、容量限制与幂等账本。管理台可维护科研服务，使用服务器批准的 endpoint / credential 引用。

这些能力不等同于普通用户可以添加任意 URL：

- 现有 MCP 实例主要来自启动配置，不是逐用户连接注册表。
- 管理台批准的地址不能直接改成用户任意地址；新增自助入口需要独立 endpoint 校验与出站策略。
- 现有凭据引用来自服务器配置；需要用户所属的加密凭据存储与只写表单。
- 普通用户的启停偏好、工具选择、OAuth 状态、连接版本与 Run 快照需要持久化。
- 当前项目使用 MCP Python SDK v1 系列；官方协议已有更新，必须按已支持 SDK 与协商版本验收，不套用新版示例后宣称兼容。

官方 2026-07-28 已移除旧协议的 GET stream / session 机制，并规定请求 SSE 断流的取消语义；2025-11-25 与更早传输的初始化和恢复不同。连接记录保留实际支持 / 协商版本；只有具体 SDK 兼容性验证通过才放开。协议请求被取消与已经提交的持久 Job 被确认取消分开处理，不能把任一流断开当成 GPU 已停止的事实。

## 3. 用户页面

### 3.1 导航与列表

侧栏在 Skills 后新增 **MCP**，使用连接图标；保留工具集。路由 `/mcp`，当前页面由同一用户 AppShell 提供，不新增一套管理后台。

页面桌面内容最大宽 740 px：

1. 标题 MCP；右上 `+ 添加连接`。
2. 搜索名称、用途与服务域名；输入框无白框，焦点反馈在搜索行背景。
3. 全部 / 平台服务 / 我的连接 / 已启用 四个紧凑过滤。
4. 连接以 **约 76 px 高的行**展示：图标、名称、一句用途；右侧状态、开关和更多操作。服务地址放详情，避免长 URL 撑大列表。
5. 次级文字入口“内网接入指南”，不把整份教程铺在首页。

同一行只保留一个启停开关，详情、认证和删除放小面板或更多菜单。无巨幅封面、渐变、指标卡或满屏开发参数。

平台服务来自已发布且授权给该用户的服务版本，普通用户只能启停和选择允许调用的工具，不能编辑平台 endpoint / 密钥。我的连接仅本人可见；本期没有“一键公开分享”，公开服务继续经管理台发布。

状态分别表达：关闭、待检查、可用、需认证、不可达、能力已变化、受限。`enabled` 是用户意图，不等于网络健康；可用状态标注最后检查时间。显示“启用 · 暂不可达”优于失败后悄悄替用户关闭。

移动端保持单列，名称和用途优先；开关与更多按钮有 44 px 触控区域。浅深主题、空状态、错误、滚动条沿用前一版规则；中英双语键名集中管理。

### 3.2 添加连接

居中约 560 px 宽的面板，分两步：

**连接信息：**名称、HTTPS MCP 地址、认证方式（服务 Token / OAuth / 无认证公开服务）、凭据输入和“测试连接”。只接收远端 HTTP MCP，不能上传命令让服务器安装或运行任意 stdio 程序。

- 地址例：`https://my-lab.ngrok.app/mcp`，不把 Token 放进 URL。
- 粘贴 `localhost` / `192.168.*` 等地址时，说明云端与本机不是同一个网络，给出内网指南；不能只报不明原因的 422。
- Token 为密码输入；存储后显示“已配置”，不提供回读明文。OAuth 按远端 MCP 授权流程跳转，不用 Supabase JWT 或 LiteLLM key 代替远端授权。
- 测试执行握手及能力发现，不调用预测工具、不占 GPU，不把 HTTP 200 当作完整连接成功。

**选择工具：**测试通过后显示真实发现的工具与短描述，用户勾选可供助手使用的工具，再“保存并启用”。默认不全选；新添加的工具不自动获得权限。OAuth 若无法完成或服务不支持可兼容协议，保留草稿与明确原因。

工具描述是远端提供的数据；显示需要转义和长度限制，不能把它当作改变平台安全策略的指令。端点要求的身份认证、已授予 scope 与平台允许调用的工具集合分别校验。

### 3.3 查看与编辑

连接详情小面板显示：名称 / 来源、域名、传输、认证状态、最后检查、允许工具、依赖它的已启用 Skills。操作：检查连接、编辑本人连接、更换凭据、关闭、删除。

更新 endpoint / 工具集合 / 凭据产生新 revision，并重新检查。已有 Run / Job 保存当时的连接版本；不能中途改 URL 后把旧调用转发至新服务。发现 schema 或工具集合变化时重新确认，不把远端新工具全部注册到 Pi。

## 4. MCP、Skill 与模型选择的关系

- **Skill** 保存领域操作说明与依赖。
- **MCP 连接** 提供已授权的能力、资源与协议入口。
- **输入框模型选择**选择负责 Agent 推理的 LLM，继续走现有 LiteLLM / Token 策略。

因此开启“蛋白预测 MCP”不会替换当前聊天模型，也不表示立刻触发预测。服务若通过 tool 调用自己的模型，按服务声明和实际执行记录计量；不能在启用时制造 LLM 调用。

全局 MCP 开关控制用户可用集合，前一版会话 Skill 选择控制本轮领域指导。Run 在当前授权、已启用连接、用户选定工具和配额允许的集合内，按需加载 Skill 依赖或当轮所需能力。未选择 Skill 也可使用用户明确请求的已授权 MCP；Skill 不会扩大工具权限，依赖缺失时不能偷偷启用连接。

会话 `+ → 连接` 可引用已启用连接，复用小型搜索 / 勾选面板；本次设计不再增加第二个常驻大型连接栏。Skill 缺少依赖时指出相应 MCP 并给出开启入口；不能绕过关闭设置偷偷启用。

大量 MCP 工具通过受控索引 / 按需能力加载，避免把所有工具 schema 与全文填进每轮上下文。用户启用服务是授权偏好，不意味着所有会话内容、文件或整个工作空间自动发给它；调用只发送该工具需要、用户有权提供的参数 / 文件。

## 5. 生命周期、任务与配额

- 开启 / 关闭连接不启动或停止用户容器；目录与偏好保存独立于容器。
- 关闭立即拒绝新工具准入，包括活动 Run 后续尚未发出的调用；已发出的远端调用不伪装为取消成功。
- 关闭后有活动 Job 时显示数量和“任务仍在运行”；可分别请求取消，并等待服务端确认。接收已经准入任务的进度 / 结果是受限续传，不允许借续传创建新计算。
- 删除连接时先处理活动任务和结果取回，再删除或禁用凭据。凭据撤销可能影响结果读取，界面需说明；不悄悄毁掉任务恢复能力。
- 自定义普通同步 MCP 工具采用有界请求，超时后结果可能未知；没有明确幂等支持时不能无条件重试有副作用调用。
- 长模型任务需远端支持平台的 submit/status/cancel/result 协议或经过验收的 MCP task 能力；仅有工具进度通知不等于持久后台任务。现有通用计算 / Task/Event 处理 Job 和唤醒，不维持一条工具 HTTP 流数十分钟。
- 用户容器主动暂停时继续遵循上一设计：结果保存，Agent 等恢复；不会因为 MCP 回调而自动开机。
- 平台服务继续执行 Token / GPU / CPU / 并发 / 文件限额；启用不能绕过配额。
- 用户自有 MCP 的 GPU/CPU 报告默认标为外部服务自报，不当作平台共享 GPU 已验证消耗，也不能给用户返还平台额度。要纳入可信平台计量需管理员发布服务并绑定已经验收的 UsageReport 来源。

## 6. 出站连接与凭据边界

这是用户自助连接成立所必需的接口边界：

1. 自定义远端只接受 HTTPS 公网 URL，不允许 userinfo、URL 密钥、片段或意外端口；密钥单独加密保存，API 返回 secret_ref / configured 状态，不回读明文。服务端密钥只发送到该连接经过检查的 origin。
2. MCP 握手、调用、重定向、OAuth metadata / token endpoints、结果文件取回都经过同一受控出站层；每次解析与实际连接验证目标，拒绝 loopback、LAN、link-local、云 metadata、IPv4/IPv6 非公网地址及 DNS 重绑定。客户端先通过一次校验不是足够保障。
3. 平台 A6000 / WireGuard 地址仅由管理员批准的连接使用，不能借普通用户表单访问云端内部网络。内网浏览器路径是另一种产品方案，不与这条限制混淆。
4. 不读取服务器代理环境变量来绕过出口策略；不向跳转目标自动转发 Authorization。TLS 证书必须校验，不能用“忽略证书”解决连通失败。
5. 远端 Token 与用户网站登录身份不同；远端请求不得附加网站 Cookie、Supabase JWT、LiteLLM key、沙箱 manager token。OAuth 有 resource / audience、state / PKCE 和回调绑定校验。
6. URL / credential 保存、检查、工具授权、调用与撤销都有 owner 和 revision；普通用户没有管理台的发布权限。
7. Schema、分页发现、内容类型、结果大小、文件下载和每用户连接数 / 频率有界；工具重名按 connection_id 分区，跨用户不能命中同一凭据缓存。

Pi 通过平台受控工具代理调用，不直接获得远端密钥或可任意访问公网的网络能力。连接名称 / 工具说明不能扩展 ACL。

## 7. 内网接入指南的用户流程

入口打开 640 px 最大宽、可内部滚动的指南面板，只先展示四步：

1. **准备 HTTP MCP**：确认本机已有可用的 HTTP MCP endpoint（例如 `127.0.0.1:8000/mcp`）。仅 stdio 或 `/predict` REST 接口不能直接填入，需先增加兼容 MCP 服务包装。
2. **开启认证**：在 MCP 服务端验证有效 Token 或 OAuth；确认未认证的连接会被拒绝。ngrok 的 agent authtoken 只认证 ngrok agent，不是服务访问 Token。
3. **开启隧道**：安装并在本人终端配置 ngrok，运行 `ngrok http http://127.0.0.1:8000`。复制当前 HTTPS 地址，只暴露专用 MCP 服务端口，不暴露数据库、管理面板或 Docker API。
4. **添加到 PSKit**：将公网地址加上实际 MCP 路径，在 Token 字段配置服务访问凭据，测试握手、勾选工具并启用。URL 改变后需更新连接并重新验证；稳定域名按 ngrok 账户可用功能配置，不承诺所有计划都支持同样选择。

常见问题折叠展示：401 / 403、404 / 405、协议不兼容、隧道离线、浏览器能打开但后端握手失败、主机休眠、长任务与取消。ngrok agent 与服务的凭据不在示例中给真实值，不引导把密码发到聊天、URL 或截图。

指南末尾说明：本机服务与隧道须保持在线；停隧道不是取消正在 GPU 上执行的任务。资源仍在本机计算，但允许工具的输入 / 输出会经过相关服务。完整操作说明另存[接入指南](../../guides/user-mcp-ngrok.md)。

## 8. 数据与 API 契约（待实现）

新增 `UserMcpConnection` / immutable `McpConnectionRevision`、`UserConnectionPreference`、`ConnectionCredential`、`McpDiscoverySnapshot`、`RunConnectionSnapshot`，与现有平台 Service/Capability 使用明确的 source/platform_ref 衔接，避免重复发布同一服务。

| 接口（`/api/v1`） | 目的 |
| --- | --- |
| `GET /mcp/connections?q=&source=&enabled=&cursor=` | 本人连接及有授权的平台连接摘要 |
| `POST /mcp/connections` | 保存本人草稿，不执行预测 |
| `GET/PATCH /mcp/connections/{id}` | 本人配置与 revision；平台来源只允许偏好字段 |
| `PUT /mcp/connections/{id}/credential` | 只写访问凭据，旧凭据不用回读 |
| `POST /mcp/connections/{id}/checks` | 受控 endpoint / 握手 / 能力发现；返回分阶段可解释结果 |
| `PUT /mcp/connections/{id}/tools` | 按已发现 schema_digest 与 revision 保存工具 allowlist |
| `PUT /mcp/connections/{id}/preference` | enabled 与 expected_revision |
| `POST /mcp/connections/{id}/authorization` | 创建本人 OAuth flow，回调由固定站点接收 |
| `DELETE /mcp/connections/{id}` | 关闭 / 删除本人连接，活动任务先得到明确处理 |

现有 `/mcp/tools` / invoke 可维持兼容，但服务端 provider 必须按 user + connection revision 获取，不能仍从进程级全局表取用户密钥。工具引用保存 connection_id / revision / remote_tool_name / schema_digest；外部 MCP session identifier 不是网站登录 session，也不是 Job 所有权。

错误 DTO 分阶段区分地址不可用、认证缺失、协议不兼容、schema 变化、调用已发出但结果未知；详细内网探测信息只留服务端审计。相同新增 / 更新请求支持幂等；检查与保存遇到 revision 变化拒绝旧结果覆写。

## 9. 交付边界与验收

先固定 UI / HTTP mock 契约，与 Skill 页面并行实现；再接逐用户注册与凭据、受控出站、能力发现与 Pi 集合，最后用用户明确授权的服务验证。

验收包含：平台与本人来源、搜索 / 启停 / 详情 / 添加 / 指南、非所有者拒绝、凭据不回读、重名工具、不执行预测的连接检查、401 / 离线 / schema 变化、OAuth callback 绑定、重定向与 DNS 重绑定、IPv6 / metadata 拒绝、已关闭连接的新调用拒绝与已有任务诚实状态、Token / GPU / CPU 计量来源、用户容器暂停、中英双语和浅深主题的桌面 / 手机布局。

真实网络测试不访问任意第三方内网服务；外部测试通过授权的 MCP 替身和本机专用服务，未知或付费预测不能作为“测试连接”执行。生产 Token / GPU 端到端验证仍需专门授权。
