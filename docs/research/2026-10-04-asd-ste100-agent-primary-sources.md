## 对架构与部署文档的可用写作推断

1. **架构文档**：为一个实体固定一个名称。先说明系统边界，再说明每个组件的职责和调用顺序。这是从 [FAQ 的术语与句法规则](https://www.asd-ste100.org/STE_faq.html)推导的写作方式，不是 Karpathy 提出的 Agent 架构。
2. **部署文档**：把执行主机、前置条件、命令、预期结果和失败时的停止点分别写明。保留路径、参数、数值、证据与安全边界。这是本项目的文档写作选择。
3. **审核**：自动规则检查可帮助发现长句和术语漂移；事实、领域术语与合规声明仍需人工核对。依据为 [官方工具说明](https://asd-ste100.org/STEsoftware.html)。

## 未确认及易误读点

- 本次未直接读取 X 原帖全文；不要把帖子解读为 Karpathy 发布了 Agent 框架或标准化部署方案。
- “80%”是 Karpathy 的非正式写作提示，没有可计算的合规分数含义；不能写成通过 80% 的 ASD-STE100 检查。
- ASD-STE100 是英语标准。把短句、固定术语、动作和条件明确化用于中文，是项目自定的中文写作规则；不能称中文内容符合 ASD-STE100。
- 未找到一手对照实验能证明该方法提高 Agent 工具调用正确率、任务成功率或系统可靠性。其可读性与执行效果需在具体产品中分别评估。
