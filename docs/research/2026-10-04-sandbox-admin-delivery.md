## 实现范围

| 范围 | 实现 |
| --- | --- |
| 用户沙箱 | 每用户独立容器与持久卷；多会话独立目录、Pi transcript 和执行状态；同会话串行 |
| 生命周期 | PostgreSQL 保存执行和文件传输 lease；活动结束有可信记录后才回收；排空后换镜像保留卷 |
| 文件与产物 | 按用户/会话验证文件所有权、摘要、大小和路径；产物入现有 Artifact 存储并计入存储额度 |
| 管理权限 | 普通 JWT 配合服务器当前角色；管理员、服务维护者、额度运营者与审计员；可撤权和受控 CLI 初始化 |
| 模型与服务 | LiteLLM alias 发布和用户/组授权；真实调用再次检查策略；科研服务草稿、连接/Schema 检查、不可变发布与审计 |
| 配额与任务 | 原子调整限额、保留已用和预占；真实任务取消和计量对账；旧 AF3 保留原生分钟口径 |
| React 管理台 | 模型、服务、发布、用户额度、沙箱、任务和审计页面；双语、双主题、分页、键盘和窄屏布局 |

模型策略默认保持 `legacy` 兼容模式。启用 `managed` 后，空授权列表不会授予任何用户访问。模型提供商密钥继续由 LiteLLM 管理；网页不接收这些密钥。

## 审查发现与修复

- 维护者同时有审计角色时，审计范围曾放行其他所有者的服务修改；现在读取和修改分别校验，修改须匹配所有者及服务范围。
- 服务再次检查失败曾保留校验资格；现在回到草稿并清除候选 digest，已发布能力快照保持原版本，并发旧检查返回 409。
- 已运行 AF3 取消曾被展示成已经停止；现在显示待确认并保留预占。新增原生分钟对账接口要求 revision、停止证据和理由，旧弱 JWT 对账路径拒绝请求。
- 文件传输期间回收/换镜像，以及排空时完成产物收集存在竞态；现在文件传输使用持久 lease，产物收集在已准入 Pi lease 释放前完成。
- 共享 MCP 并发 lease 的异步心跳可能被同步认证/数据库阻塞；专用续租线程避免这个延迟，退出时先停止并等待续租再释放容量。
- 完整回归捕获同一 Run 的原始 Token 记录时间回退约 5.1 秒，按时间排序把第二次调用放到了第一次之前。新增公开 HTTP 时钟回拨测试先失败，再修正展示顺序：每种账本保留追加顺序，以不回退的排序键合并资源，原始时间和计费金额保持不变。

这些问题均保留了公开 HTTP 或渲染行为的失败与通过记录。因当前线程的代理数量上限，完成前审查由前端实施者审查其未实施的后端/沙箱部分，主代理审查前端、集成和最终验证。

## 部署与计量边界

本轮在本地隔离 PostgreSQL、Docker 和浏览器验证，没有更新远程 Staging 或生产。HTTP 和 Pi 的外部模型边界使用合成身份及确定性服务；没有付费推理或真实 GPU 调度验收。

用户容器与会话目录的隔离已验证，但 Pi 仍使用已注册的受限工具模式。不同会话目录不代表不同 UID 或内核隔离；任意 shell/Python 工具尚未开放。沙箱容器 CPU 总量属于用户级监控，不作为各会话的重复计费记录。

通用服务用量由维护者按协议上报，未知值保留 `null`。服务准入限制和执行中的硬停止能力分别声明；自报 CPU/GPU 耗时不代表硬件核验。旧 AF3 仍为 `legacy_wall`，与 GPU 设备毫秒独立处理。

v5、v6 数据库 migration 需显式执行。生产启用前须备份 PostgreSQL，并使用识别当前 schema 的镜像回退；有沙箱/管理记录时拒绝有损 SQLite 导出。用户持久卷不随容器清理删除。发布使用现有云端部署 skill，测试身份、数据及密钥不进入生产。
