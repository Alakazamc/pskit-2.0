# 对话输入框的本地草稿与模型偏好

日期：2026-10-05。范围：`new_frontend` 的现有对话输入框；未发布云端、未改变后端数据库或启动真实模型 / GPU 任务。

## 原因与修复

原输入框共用单例 Zustand 状态，没有按用户 / 对话保存草稿；默认模型直接跟随 API 数组第一项。组件复用时，文字、上下文和上传控件可能进入下一对话。

现在每个输入框按用户和会话创建独立 store，在渲染前读取带版本的浏览器 localStorage。已发送消息的执行参数仍随正常消息请求提交；未发送草稿与选择偏好只在浏览器保存。

- 缓存：文字、模型 ID、推理强度、已经上传成功的文件 / Skill / Resource ID 与名称。
- 身份：用户 ID + 会话 ID；已有会话移动项目后仍使用原会话缓存。个人 / 项目新聊天各有独立草稿。
- 新聊天：创建会话时将草稿转到实际 session；拒绝提交后可原位重试或刷新恢复。
- 接受提交：只清除本次提交的文字 / 引用，保留模型偏好和用户后来输入的文字。
- 异步：旧输入框的上传完成 / 请求返回仍绑定原草稿，并读最新本地状态，避免覆盖重开后的文字。
- 边界：临时 blob URL、文件正文和凭据不存入草稿。损坏 / 不兼容缓存恢复为空；读写不可用或容量耗尽时保留当前内存编辑状态，浏览器未成功保存的数据无法保证刷新恢复。

上述规则已补入 `new_frontend/AGENTS.md`。
